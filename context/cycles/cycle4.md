## Purpose

Reserve the next delivery cycle and provide a consistent place to record discovery, scope,
acceptance criteria, and sequencing before implementation begins.

## Planning questions

- What user or operator problem is the highest-value follow-up to Cycle 3?
- What evidence from live usage supports addressing it now?
- Which existing phase boundary owns the work?
- What is explicitly out of scope?
- What verification will demonstrate that the cycle is complete?

## Workflow

1. Review Cycle 3 live evidence and outstanding limitations.
2. Define a concrete objective, scope, non-goals, and acceptance criteria.
3. Select a branch name and ordered implementation steps.
4. Implement one step at a time, verify it, commit it, and pause before the next step.
5. Run full live verification before closing, merging, tagging, or releasing the cycle.

## Guardrails

- Preserve the local-first, single-user product boundary unless a future decision explicitly
  changes it.
- Keep forecasting and recommendation outputs transparent and evidence-backed.
- Do not introduce automated trading or guaranteed-profit claims.
- Prefer measured user or operational needs over speculative platform expansion.
